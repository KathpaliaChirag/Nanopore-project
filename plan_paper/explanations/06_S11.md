# S11 - first scanner attempt (null result)

built on: S10.

## what it is

two changes to `MinimizerScanner`, the code that slides a window over the
DNA sequence and tracks the smallest k-mer in it - `perf` showed this scanner
at roughly a third of all CPU cycles.

**1. ring buffer instead of `std::deque`.** the scanner keeps a small sliding
window of candidate k-mers in a queue. `std::deque` allocates in chunks and
has map-style indirection; a fixed-size ring avoids both:

```cpp
struct MinimizerRing {
  static const size_t CAP = 256;
  MinimizerData buf[CAP];
  size_t head = 0, n = 0;
  inline void push_back(const MinimizerData &d) { buf[(head + n) & MASK] = d; n++; }
  // ... clear/empty/front/back/pop_front/pop_back, same semantics as deque
};
```

**2. one instruction instead of five for reverse-complement.** stock does
three separate mask-and-shift stages to swap bytes, then byte-pairs, then
halves of a 64-bit word - which is exactly what `__builtin_bswap64` does in
one instruction:

```cpp
// before: swap bytes, swap byte pairs, swap halves (3 stages)
// after:
kmer = __builtin_bswap64(kmer);
```

## result

**no gain.** CPU time (`user` time from `/usr/bin/time`) came back identical
to S10's: 300.44s vs 301.90s on a repeated test - within noise. wall-clock
was unchanged.

## why it didn't work (found later, in S18)

`perf annotate` on this same code, done two stages later, found that one
instruction - a 16-byte load immediately after the ring's `push_back` had
just written that same 16 bytes as two separate 8-byte stores - was eating
21% of the scanner's time on its own. a wide load right after two narrow
stores can't be served from the store buffer and stalls waiting for the
stores to retire and land in cache. the ring buffer here was the right
shape, but the `push_back(const MinimizerData &d)` signature still built the
struct as a stack temporary and copied it in as 16 bytes, so it hit the exact
same stall `std::deque` would have. the fix (S18) was to never materialize
that struct at all - write the two fields straight into the slot.
