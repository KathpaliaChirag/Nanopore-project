# S17 - rolling reverse-complement + a portability guard

built on: S16.

## original code: what it was doing

for every position of the sliding window, the scanner needs the
reverse-complement of the current k-mer, to pick a strand-independent
("canonical") representation. stock recomputes it from scratch each time:

```cpp
uint64_t canonical_lmer = dna_ ? canonical_representation(lmer_, l_) : lmer_;
// canonical_representation calls reverse_complement(), 5 mask/shift stages,
// on the FULL k-mer, every single position
```

## the issue

the window only moves by one base at a time - one character leaves at one
end, one enters at the other. recomputing the full reverse-complement from
scratch throws away almost all of the previous computation every time.

## new code: what changed

maintain a second register, `rc_lmer_`, that tracks the reverse-complement of
the window incrementally. sliding the window by one base only needs a shift
and inserting the complement of the new character:

```cpp
// in the per-character loop, alongside updating lmer_ itself:
if (dna_)
  rc_lmer_ = (rc_lmer_ >> 2) | ((uint64_t)((~lookup_code) & 3u) << (2 * (l_ - 1)));
```
(2-bit DNA codes: complement is just `3 - code`, i.e. `~code & 3`.)

```cpp
// picking the canonical form becomes a comparison, not a recomputation:
canonical_lmer = lmer_ < rc_lmer_ ? lmer_ : rc_lmer_;
```

this only applies for DNA with the current reverse-complement convention
(`revcom_version_ != 0`); older databases and protein sequences keep the
original, unchanged code path.

**separately, a portability fix in the same stage:** S12's fast modulo
(`FastMod`) used 128-bit integers (`unsigned __int128`), which not every
compiler or target supports. it now checks for that at compile time and
falls back to plain `%` when it isn't available:

```cpp
#ifdef __SIZEOF_INT128__
    /* the FastMod trick from S12 */
#else
    return hc % capacity_;   // no 128-bit integers on this compiler/target
#endif
```

## why the result is still correct

the derivation: the reverse-complement convention this codebase uses places
`comp(s_k)` at bit-pair position `k`, oldest base first. sliding the window
by one drops the oldest base (which was at the top bit-pair) and inserts the
complement of the newest base at the bottom - exactly what the shift-and-insert
does. this was checked against stock's `canonical_representation()` output
with correctness tests (12 kraken2 modes, including quick mode and paired-end)
before and after, byte-identical both times.

## result (3 interleaved reps, 1,872,777 reads, 32 threads)

50MB: 8.72s to 8.40s. 8GB: 8.17s to 7.92s. on a pinned 8-core run: user CPU
time dropped about 5%.
