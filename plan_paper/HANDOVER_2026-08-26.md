**New findings from today's deeper exploration (after the audit, same day):**
1. **Eviction policy is a real, independent lever from capacity.** Built a "pinned" variant (protects any cache entry that's been hit at least once from eviction, instead of blind round-robin) — real hit-rate improvement at every capacity tested, and **the relative improvement is largest when capacity is smallest** (+25% at 4,096 sets, shrinking to +4% at 262,144 sets). This directly strengthens the case for S4 (biology-aware eviction) over just growing S2's size.
2. **A second, distinct hard ceiling on cache size, separate from the earlier memory-init slowdown cliff (which kicks in around 1M+ sets/64MB+ per thread):** at 262,144 sets (only 16MB/thread), the cache **segfaults** under multi-threading (confirmed: exit code 139) despite trivial total RAM usage. Leading hypothesis: glibc's static TLS (thread-local storage) allocation limit — creating many OpenMP threads that each need a large `thread_local` array reserved at thread-creation time can exceed that budget, independent of how much RAM is actually free. **Real fix (not yet implemented): use a `thread_local` pointer, heap-allocated once per thread on first use, instead of a static `thread_local` array.** This is a real constraint S3's sizing design needs to account for.
3. Both eviction-policy patches now print their own configured size in every run (`size=%zu ways=%zu`) — binaries are self-labeling, can't be mistaken for each other.

**Everything is committed and pushed to GitHub** — `plan_paper/command_log.md` has the full chronological detail, all patch/build/comparison scripts are in `plan_paper/scripts/`, all patch diffs in `plan_paper/patches/`.

## Operational knowledge (unchanged from before, still true)

- Luna proxy needs explicit `unset http_proxy https_proxy HTTP_proxy HTTPS_proxy` (not just `env -u`) before `iitd-login.py`, since the exports are baked into `~/.bashrc`. Login session lasts ~100s/cycle — retry real operations in a loop.
- Benchmarks must **interleave** binaries within each cell, never run separate sequential blocks — caught a page-cache-warmth artifact this way once.
- **This terminal corrupts long pasted text** (dropped/duplicated heredoc lines, mangled base64) — for any script over a few lines, commit it to GitHub and `curl` the raw URL on Luna instead. Verify with `diff` against local before trusting it, and `py_compile`/`bash -n` before running.
- `git tag` right after a failed `git commit` still runs if not `&&`-chained — always verify a tag with `git log -1 <tag> --format='%H %s'` after creating it.
- User wants commands explained in detail: inline `#` comments in the code/command itself (why each line matters), then a short paragraph tying it together — not just a one-line "why."
- Commit + push after every real step, not batched.
