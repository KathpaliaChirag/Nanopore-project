## design as built

files changed: src/classify.cc (ProcessFiles), src/seqreader.h (LoadPread, LoadPreadTry, loaded(), rbuf_), new src/preadfq.h (all the logic, no kraken dependencies so the test includes it directly).

1. setup, before the parallel region. if K2_PREAD is not "0", filename1 is not stdin and opts.paired_end_processing is off, a k2pread::Plan is built over filename1 plus g_extra_files in order. Plan::Init opens every file, requires fstat S_ISREG, records the size, and pre-scans the first min(1 MiB, size) bytes: byte 0 must be '@' and every complete record in that MiB must pass the strict parser (an incomplete record at the end of the MiB is fine). any failure (cannot open, fifo, /dev/null, FASTA, multi-line, blank line between records, junk first, length mismatch) makes Init return false and the whole run uses the old kseq path from the start. nothing is partially converted. an empty file is fine and has zero chunks. K2_PREAD_VERBOSE=1 prints on or off plus the reason to stderr. K2_PREAD_CHUNK=<bytes> overrides the 4 MiB chunk size (for testing).
2. tickets. cum[f] is the prefix sum of ceil(size_f / B) over files. the thread loop does `t = __atomic_fetch_add(&plan.next, 1)`; `block_id = t`; `ok_read = t < plan.total`. Locate(t) is an upper_bound on cum giving (file f, chunk k). no lock, no omp critical. the old `critical(seqread)` block is untouched and still used when use_pread is false. an empty chunk returns ok_read true with zero records, so it classifies nothing and still pushes an empty OutputData with its block_id, so next_output_block_id cannot stall. threads that draw t >= total break out exactly as `!ok_read` did before. InitializeOutputs is now skipped by a thread whose block has zero records (it would otherwise read an indeterminate file_format_ from a copied reader); the old path always has at least one record there so it is unchanged.
3. chunk read (read_chunk). chunk k owns the records that START in [off_s, off_e) with off_s = k*B and off_e = min(off_s+B, size). the thread preads file bytes [off_s-1, off_e + tail) into its own std::vector<char> (the extra leading byte tells whether off_s is a line start; tail starts at 64 KiB). if any scan runs out of buffer before eof the result is PR_MORE, the tail is multiplied by 4 and the chunk is re-read and re-parsed from scratch (needed only for reads longer than about 60 kB, which are rare, and nothing is shared so it is just local rework).
4. record start rule (find_start). from byte p, the first line start L >= p (L == p only if p == 0 or byte p-1 is '\n') such that the line at L starts with '@', the line at L+2 starts with '+', and the effective lengths of lines L+1 and L+3 are equal (effective length uses kseq's rule below). a quality line beginning with '@' is followed by a header and then a sequence line, which cannot start with '+', so the L+2 test rejects it. an empty read at eof whose empty quality line is simply missing is accepted as kseq accepts it. if no candidate exists the answer is the file size.
5. the strict parser (parse_record), copied from kseq semantics: header line must start '@'; name = bytes up to the first isspace byte (space, \t \n \v \f \r); comment = the rest of the header line after that one byte, with one trailing '\r' removed only when that rest is longer than 1 byte; no delimiter before the line end means empty comment; sequence line = line 2, trailing '\r' removed only when the line is longer than 1 byte (so a CRLF empty read has seq "\r" of length 1, exactly like kseq), empty allowed, must not start with '@', '+' or '>'; line 3 must start with '+', rest ignored; quality line = line 4 with the same '\r' rule, effective length must equal the sequence length; an unterminated last quality line at eof is accepted. flags exactly as copy_from_kseq: FASTQ iff quality length > 0 (an empty read is flagged FASTA), quals are cleared when k2_skip_qual() is set else copied. file_format_ becomes the format of the last record in the block, as before.
6. runtime guard (process_chunk). F = find_start(off_e) (or the file size for the last chunk), S = find_start(off_s) (0 for chunk 0). the chunk parses records from S while the record start is < off_e. after the loop the end position q of the last record must equal F, which is the start the next chunk will compute with the same function on the same bytes. every record must be strict. so chunks tile the file exactly, and a false start from find_start can only cause a loud failure, never a silent difference. trailing bytes after the last record are accepted only if they contain no '@' and no '>' (kseq skips such bytes, for example a final blank line). any other violation returns PR_BAD.
7. failure policy. there is no per-chunk re-parse with the old path, because once a file is not strict 4-line fastq the chunk boundaries have no defined meaning. a PR_BAD in a chunk prints `classify: K2_PREAD failed on ticket N: <reason>. rerun with K2_PREAD=0` and calls _exit(3). the up-front pre-scan makes this rare, but a file that is clean in its first MiB and damaged later (or has a blank line or multi-line record later) aborts instead of producing different output. kseq would have handled a late blank line; we abort. that is the safe direction.
8. paired end (LoadBatch paths), stdin, pipes, gz (this build has no gz) and non-regular files never build a plan and run the old code unchanged.

## known risks

- no end-to-end run yet. the omp loop change is small but the empty-chunk and thread-exit logic have only been read, not run. first check: a tiny input (one file under 4 MiB, so one chunk and many idle threads) and a file whose size is an exact multiple of B.
- aborts instead of falling back when a file is clean in its first MiB and non-strict later (late blank line, multi-line record, truncated last record, garbage between records). run is lost, not wrong. K2_PREAD=0 reruns it. if this matters, extend the pre-scan to a cheap whole-file strict-count pass (cost about one extra read of 12.5 GB, which is exactly the thing we are removing), or sample several offsets per file.
- a truncated final record (missing lines at eof) is handled by kseq as a dropped record; we abort. a final record that is an empty read with the final empty quality line missing is accepted.
- each chunk reads 64 KiB of tail beyond B (about 1.6% extra reads from the page cache), plus a few KB before it; chunks longer than the tail are re-read with a 4x tail. reads longer than about 60 kB trigger one retry for the chunks they straddle.
- the find_start rule assumes sequence lines never start with '+', '@' or '>', which is also enforced by the parser. a fastq whose sequence line starts with one of those is rejected by the pre-scan or aborts.
- a fastq where a '+' line is a duplicate of the header is fine (the rest of the '+' line is ignored); a quality line equal to '+' is fine.
- 192 cores, many threads preading the same 16 files: page-cache locking is expected to be fine but is unmeasured; the 12.5 GB must be in page cache or the first pass is disk bound for both paths equally.
- output order depends only on block_id and record order inside a block, and chunk boundaries do not move records between blocks in a way that changes order, so the output must be byte-identical; this is argued, and tested at reader level only. the k-mer cache and per-thread state are untouched, but block composition differs from the old path (4 MiB of bytes instead of 3 MiB of bases), so any statistic that depends on block cuts (none known) would differ.
- file_format_ for InitializeOutputs is the format of the last record in the first non-empty block that initialises; same rule as before but with different block cuts, so a mixed FASTA/FASTQ-flag corner (an empty read last in a block) could in principle pick FASTA for the output format. this was already block-cut dependent in the old path.

## summary (6 lines)
1. added a lock-free reader (K2_PREAD, default on, K2_PREAD=0 forces the old path): atomic ticket = block_id, ticket maps to (file, 4 MiB chunk), thread preads and strictly parses its chunk outside any lock; empty chunks still emit an empty output block.
2. plan decided up front (fstat regular files plus a 1 MiB strict pre-scan per file; paired end, stdin, pipes and anything non-strict use the old path unchanged); runtime guard checks every chunk tiles exactly and aborts with a clear error (rerun K2_PREAD=0) rather than ever differing silently.
3. kseq semantics copied exactly (name to first isspace, comment rule, '\r' stripped only when length > 1, FASTQ iff quality length > 0, skip-qual honoured).
4. unit test old vs new: 8101 cases, 0 failures (edge files, chunk sweep 1..260 bytes and up to 4 MiB, multi-file, 600 fuzz, late damage, 3 real pod5 files); a deliberately broken rule is detected.
5. built clean at ~/e1/bin_pread (classify not run on any data or database); diff in code/impl_pread.diff, test in code/test_pread.cc.
6. unit test passed: yes; end-to-end byte-identity, the omp loop with empty chunks, and the speedup are still unmeasured.
