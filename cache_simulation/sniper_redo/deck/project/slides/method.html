How we measured

  1. Run the same kraken2 program every time (its own software cache is switched off)
  2. Sniper, a CPU simulator, models Luna: L1 48 KB, L2 2 MB, LLC 2.25 MB per core
  3. Change one hardware property per run
  4. Compare the simulated time with an unmodified run, called base: no prefetcher

time saved (%) = (base − variant) / base × 100

Example: 8 GB database, 8 cores, 50 reads. Base 8,880.7 µs, with prefetchers 7,265.8 µs, so 18.2% saved. Higher means faster.

190 runs: 8 GB and 16 GB databases; 10, 25 and 50 reads; 1, 4, 8 and 16 cores. The metric is the simulated time of the slowest core.

Only one thing changes between a variant and its base, so any difference in time is caused by that change. The unmodified base has no prefetcher at all; that matters for how much of the result would carry over to the real machine, which already has prefetchers (see the last slide).
