kraken2 spends its time looking things up

A DNA read from the sequencer

→

Cut into short pieces (k-mers)

→

Look each piece up in a hash table of 8 GB or 16 GB

→

Vote: which species is this read?

Each lookup lands at an unpredictable place in a table far bigger than any CPU cache. That is the step we wanted to speed up.

Project question: can a different cache design make those lookups faster?

A k-mer is a short string of k letters taken from the read. The hash table maps each k-mer to the species that contain it. Because the table is gigabytes, almost every lookup goes to main memory rather than a cache.
