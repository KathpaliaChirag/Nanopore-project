With more reads the gain falls on one core and rises on four

How to read it

Same height as before: time saved by the prefetchers. The horizontal axis is how many reads were classified.

What we found

One core: 11.9% falls to 4.0%. Four cores: 12.7% rises to 15.8%.

Caution

At 50 reads the instruction count rises from 52 M (1 core) to 87 M (8 cores) and 130 M (16 cores): thread start-up work. Part of the multi-core gain may come from that. Untested.

To settle it

Run 8 and 16 cores with a few hundred reads each.

Fifty reads is about three reads per core at 16 cores, so start-up and splitting overhead is a large share of the run. On one core the early gain is largely a fixed start-up saving, which is why the percentage falls as reads are added. Sniper would need many hours per run for a few hundred reads on many cores, which is why this was not done yet.
